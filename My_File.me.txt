8. JWT (JSON Web Token)
- JWT has 3 parts separated by dots:
  - Header
  - Payload (Base64 encoded, NOT encrypted, anyone can decode)
  - Signature

- Purpose of Signature:
  - Ensures the Header and Payload have not been modified.
  - Proves who issued the JWT.

----------------------------------------------------

i. Symmetric JWT (HS256)

- Uses ONE shared Secret Key.
- The same Secret Key is used to:
    1. Sign (create) the JWT
    2. Verify the JWT
- Best when the same backend both creates and verifies the token.
- Example:
    - Your Rust Backend
    - Access Tokens
    - Refresh Tokens

----------------------------------------------------

ii. Asymmetric JWT (RS256)

- Uses TWO keys:
    - Private Key
    - Public Key

- Private Key
    - Used ONLY to sign the JWT.
    - Never shared.

- Public Key
    - Shared publicly.
    - Used ONLY to verify the JWT signature.
    - Cannot create/sign new JWTs.

- Firebase / Google Flow

    Google
        ↓
    User signs in
        ↓
    Google creates ID Token (JWT)
        ↓
    Google signs it using Google's Private Key
        ↓
    Frontend receives the ID Token
        ↓
    Frontend sends ID Token to your backend
        ↓
    Backend downloads Google's Public Certificate
        ↓
    Extracts Google's Public Key
        ↓
    Verifies:
        - Signature
        - Audience (aud)
        - Issuer (iss)
        - Expiry (exp)
        ↓
    If all checks pass,
    Backend trusts the user's identity.
